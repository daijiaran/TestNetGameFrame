## 1. 项目概述

这是一个基于 Unity 的多人在线射击项目，采用客户端/服务端架构，网络传输使用 UDP，自定义二进制协议使用 `DJRNetLib` 实现。

当前项目的核心目标可以概括为：

- 客户端负责输入、显示、相机、UI
- 服务端负责玩家实体、怪物、子弹、碰撞、伤害、世界状态
- 共享层负责网络包定义和序列化/反序列化

从代码职责上看，这个项目已经具备了：

- 启动客户端/服务端
- 玩家加入
- 玩家移动与攻击
- 服务端生成玩家和怪物
- 服务端子弹命中判定
- 玩家和场景物体同步
- 玩家死亡和游戏结束 UI

## 2. 使用了什么

## 2.1 引擎与基础框架

- `Unity`
- `MonoBehaviour` 组件模式
- `Resources.Load` 动态加载预制体
- `TextMeshPro`
- `UnityEngine.InputSystem`

说明：

- 输入层使用的是新版输入系统，比如 `Keyboard.current`、`Mouse.current`
- UI 文本已经主要使用 `TextMeshProUGUI`
- 资源加载依赖 `Resources/Prefabs/...` 路径

## 2.2 网络与并发

- `System.Net.Sockets.Socket`
- `SocketType.Dgram`
- `ProtocolType.Udp`
- `BinaryWriter / BinaryReader`
- `ConcurrentQueue`
- `Task.Run`

说明：

- 客户端和服务端都直接使用原生 UDP Socket
- 协议采用手写二进制序列化，不依赖第三方网络框架
- 客户端收包在后台线程中进行，再通过队列切回 Unity 主线程

## 2.3 架构手段

- 单例基类 `SingelBase<T>`
- 接口抽象
- 组件装配
- 事件回调 `Action`

当前已经存在的接口包括：

- `INetworkService`
- `IPlayerManager`
- `ISceneObjectManager`
- `IServerCommandHandler`
- `IClientRegistry`
- `IWorldStateProvider`

这些接口主要用于服务端解耦。

## 3. 顶层目录结构

`Assets/Scripts` 当前主要分成下面几个区域：

```text
Assets/Scripts
├─ Client/                 # 客户端逻辑
├─ Server/                 # 服务端逻辑
├─ Shared/                 # 客户端与服务端共享协议/数据结构
├─ GameRoot/               # 启动入口
├─ Conmon/                 # 通用基础组件
├─ *.md                    # 项目说明和分析文档
```

各目录含义：

- `Client/`：输入、网络接收后的场景还原、UI
- `Server/`：服务端网络处理、实体管理、怪物、子弹、状态同步
- `Shared/`：包定义、共享数据、协议枚举
- `GameRoot/`：决定启动客户端还是服务端
- `Conmon/`：公共单例基类

## 4. 启动入口层

## 4.1 `SingelBase<T>`

文件: [SingelBase.cs](/f:/UnityProject/MyNetGameProject/src/Client/Assets/Scripts/Conmon/SingelBase.cs)

职责：

- 给需要全局访问的组件提供 `Instance`
- 在 `Init()` 中处理重复单例

特点：

- 这是一个 Unity 场景内单例
- 不是静态纯类，而是挂在 `GameObject` 上的组件

典型使用者：

- `GameRoot`
- `ClientRoot`
- `Server`
- `NetworkPlayerManager`

## 4.2 `GameRoot`

文件: [GameRoot.cs](/f:/UnityProject/MyNetGameProject/src/Client/Assets/Scripts/GameRoot/GameRoot.cs)

职责：

- 总入口
- 根据 `isServer` 决定挂载 `ServerRoot` 还是 `ClientRoot`

关键方法：

- `GameInit()`
- `StartServer()`
- `StartClient()`

说明：

- 当前项目不是两个独立可执行程序
- 而是在同一套 Unity 工程里切换“服务端模式”和“客户端模式”

## 4.3 `ClientRoot`

文件: [ClientRoot.cs](/f:/UnityProject/MyNetGameProject/src/Client/Assets/Scripts/GameRoot/ClientRoot.cs)

职责：

- 初始化客户端 UI
- 创建 `NetConect`
- 启动接收线程
- 用户加入游戏后实例化客户端同步管理器

启动流程：

1. `Start()` 中实例化 `GameStart` 面板
2. 监听 `StartGamePanel.GameStarteEvent`
3. 创建 `NetConect`
4. 调用 `netConect.ReceiveInformation()`
5. 玩家输入名字后，实例化：
   - `NetworkPlayerManager`
   - `NetworkScensItemManager`

额外职责：

- 管理 `GameOverEvent`
- 在 `GameOver()` 中弹出结束面板

## 4.4 `ServerRoot`

文件: [ServerRoot.cs](/f:/UnityProject/MyNetGameProject/src/Client/Assets/Scripts/GameRoot/ServerRoot.cs)

职责：

- 在 `Start()` 时挂载 `Server`

说明：

- `ServerRoot` 很薄
- 真正的服务端装配逻辑都在 `Server.cs`

## 5. 当前层次结构

从“职责层次”看，当前项目大致可以分成以下五层：

```text
1. 入口与生命周期层
2. 客户端表现与输入层
3. 服务端仿真与状态管理层
4. 网络与协议层
5. 场景对象与战斗对象层
```

更具体的结构如下：

```text
GameRoot
  -> ClientRoot / ServerRoot

ClientRoot
  -> NetConect
  -> NetworkPlayerManager
  -> NetworkScensItemManager
  -> UI Panels
  -> PlayerControl / Client 场景对象

ServerRoot
  -> Server
    -> ServiceUpdate
    -> ServerCommandHandler
    -> ClientRegistry
    -> ServerStateSyncService
    -> ServerWorldStateProvider
    -> ServerAllPlayerManager
    -> ServerAllitemManager
    -> MonsterSpawn
    -> PlayerInstance / Server 场景对象 / Monster / Bullet

Shared
  -> PacketType
  -> PacketBase
  -> 各类 Packet
```

## 6. 客户端层

客户端主要负责三件事：

- 读取输入
- 接收服务端同步
- 把同步结果还原成场景中的对象与 UI

## 6.1 `NetConect`

文件: [NetConect.cs](/f:/UnityProject/MyNetGameProject/src/Client/Assets/Scripts/Client/NetConect.cs)

职责：

- 客户端 UDP 通信类
- 发送加入、移动、攻击等数据包
- 后台线程接收服务器广播
- 把接收到的数据压入线程安全队列
- 在 `Update()` 中把队列消费到 Unity 主线程

当前暴露的事件：

- `takeMessage`
- `errCallback`
- `netUserJoinEvent`
- `takePlayerPacket`
- `takeSceneItemPacket`

内部队列：

- `_msgQueue`
- `_packetQueue`
- `_ScenesIteamDataQueue`

说明：

- 这里采用的是典型“生产者-消费者”模型
- 后台线程只负责收包和反序列化
- Unity 对象的更新放在主线程 `Update()` 中

## 6.2 `NetworkPlayerManager`

文件: [NetworkPlayerManager.cs](/f:/UnityProject/MyNetGameProject/src/Client/Assets/Scripts/Client/NetworkPlayerManager.cs)

职责：

- 管理客户端所有玩家对象
- 创建当前玩家 `PlayerSelf`
- 处理其他玩家加入
- 同步其他玩家的位置、旋转、朝向、死亡状态
- 负责把输入命令转发给 `NetConect`

核心字段：

- `PlayerPrefab`
- `PlayerSelf`
- `players`
- `CurrentPlayerIP`
- `deadIPs`
- `playerGameData`

几个关键点：

- `deadIPs` 用于防止死亡玩家被乱序包重新激活
- `players` 以 `Ip` 作为索引管理所有玩家
- 当前玩家对象和远端玩家对象都复用 `PlayerControl`

关键方法：

- `GameStart(string name)`
- `Join(UserJoinPacket joinPacket)`
- `synchronousOtherPlayer(...)`
- `SendMoveToSever(...)`
- `SendAttackToServer(...)`

## 6.3 `PlayerControl`

文件: [PlayerControl.cs](/f:/UnityProject/MyNetGameProject/src/Client/Assets/Scripts/Client/Player/PlayerControl.cs)

职责：

- 玩家表现控制器
- 本地玩家输入采集器
- 本地玩家相机控制器

对本地玩家实现的功能：

- 键盘移动输入
- 鼠标朝向
- 鼠标左键持续攻击
- 鼠标右键旋转相机
- 鼠标滚轮缩放相机

网络相关实现：

- `Move()` 中构造 `UserMovePacket`
- `SendAttack()` 中构造 `UserAttackPacket`
- 调用 `NetworkPlayerManager.Instance` 把输入发到服务端

说明：

- 客户端并不直接驱动最终世界状态
- 客户端上传的是“输入意图”
- 最终位置和旋转以服务端广播为准

## 6.4 `NetworkScensItemManager`

文件: [NetworkScensItemManager.cs](/f:/UnityProject/MyNetGameProject/src/Client/Assets/Scripts/Client/NetworkScensItemManager.cs)

职责：

- 管理场景物体同步
- 根据 `ScenesItemDataPacket` 创建、更新、销毁对象

数据结构：

- `AllItemInstance`

关键行为：

- 对象存在则更新 transform
- 不存在则从 `Resources/Prefabs/` 动态创建
- `isDestroy == true` 时销毁对象

说明：

- 这里的“场景物体”包含可同步的子弹、怪物等实体
- 客户端本身不做判定，只做还原

说明：

## 8.1 `PlayerInstance`

文件: [PlayerInstance.cs](/f:/UnityProject/MyNetGameProject/src/Client/Assets/Scripts/Server/Player/PlayerInstance.cs)

职责：

- 服务端玩家实体
- 应用移动输入
- 应用攻击输入
- 处理死亡

具体实现：

- `ApplyMoveInput()`：
  - 根据 `UserMovePacket` 计算前进和横移
  - 写入 `rigidbody.linearVelocity`
  - 同步角色正朝向
  - 同步枪口 `FaceDirection`
- `ApplyAttackInput()`：
  - 根据 `UserAttackPacket` 生成子弹
  - 注入场景对象管理器和网络服务
  - 忽略子弹和自己碰撞
- `OnDisable()`：
  - 从玩家管理器移除自己
  - 标记 `isDead = true`
  - 广播销毁状态

说明：

- 这是服务端真正的玩家业务实体
- 客户端只负责显示对应结果

- `H`, `V`

- `Attack_x`, `Attack_y`, `Attack_z`

说明：

- 它不是位置同步包
- 而是“输入命令包”

### `UserAttackPacket`

职责：

- 上传攻击行为

字段：

- `BulltType`
- `Prefabsname`

## 9.4 世界快照包

### `UserPositionAndStatusPacket`

职责：

- 表达服务端玩家状态快照

字段：

- `Name`
- `R_X`, `R_Y`, `R_Z`
- `X`, `Y`, `Z`
- `Attack_X`, `Attack_Y`, `Attack_Z`
- `Health`
- `isDead`
- `Ip`

### `ScenesItemDataPacket`

职责：

- 表达场景物体状态快照

- `R_x`, `R_y`, `R_z`

说明：

## 9.5 包设计特点

当前包层采用的是：

- 包对象 = 数据对象
- 包对象 = 序列化器
- 包对象 = 反序列化器

优点：

- 简单直接
- 好理解

代价：

- 业务层很容易直接操作网络包字段
- 协议层和状态层会有一定耦合

## 10. 当前主要消息流

## 10.1 客户端输入到服务端

```text
PlayerControl
  -> NetworkPlayerManager
    -> NetConect
      -> UDP Socket
        -> ServiceUpdate
          -> ServerCommandHandler
            -> ServerAllPlayerManager / PlayerInstance
```

说明：

- 客户端上传的是输入
- 服务端决定实体怎么移动、怎么攻击

## 10.2 服务端世界状态广播到客户端

```text
ServerAllPlayerManager / ServerAllitemManager
  -> ServerWorldStateProvider
    -> ServerStateSyncService
      -> ServiceUpdate.SendToClient()
        -> NetConect.ReceiveInformation()
          -> ConcurrentQueue
            -> NetConect.Update()
              -> NetworkPlayerManager / NetworkScensItemManager
```

说明：

- 这是当前项目最重要的同步链
- 客户端不依赖本地推演，而是还原服务端广播结果

## 10.3 对象生命周期同步

```text
ServerScenesObjectBase.InitOBJ()
  -> sceneObjectManager.AddAllItem()
  -> ServerStateSyncService 广播创建/更新快照

ServerScenesObjectBase.OnDisable()
  -> sceneObjectManager.RemoveScenesItem()
  -> 广播 isDestroy = true
  -> 客户端收到后销毁对应对象
```

玩家死亡链也类似：

```text
PlayerInstance.OnDisable()
  -> playerManager.RemovePlayer()
  -> UserPositionAndStatusPacket.isDead = true
  -> 广播死亡包
  -> 客户端删除玩家对象
```

## 11. 当前架构特点

## 11.1 已经实现的优点

- 服务端已经从“网络层直调业务层”拆成了：
  - `ServiceUpdate`
  - `ServerCommandHandler`
  - `ServerStateSyncService`
- 客户端已经正确区分了：
  - 后台线程收包
  - 主线程消费和更新 Unity 对象
- 怪物、子弹、伤害判定都在服务端
- 玩家和场景对象都具备基本同步链路

## 11.2 仍然保留的结构特征

- 单例仍然很多
- 客户端还直接消费 `Packet DTO`
- `Resources.Load("Prefabs/...")` 仍大量硬编码
- `ServerAllPlayerManager` 和 `ServerAllitemManager` 仍同时承担：
  - 业务状态管理
  - 同步包数据维护
- `NetTalk` 仍是独立网络链路，没有纳入统一客户端通信入口

## 11.3 当前可以怎样理解这个项目

如果用一句话总结：

**这是一个“客户端上传输入、服务端做世界仿真、服务端按快照广播、客户端负责还原显示”的 Unity UDP 多人游戏原型。**

## 12. 代码阅读建议

如果后续要继续读这个项目，建议按下面顺序：

1. `GameRoot -> ClientRoot / ServerRoot`
2. `Server -> ServiceUpdate -> ServerCommandHandler`
3. `ServerAllPlayerManager / PlayerInstance`
4. `ServerAllitemManager / ServerScenesObjectBase / Bullet / Monster`
5. `NetConect -> NetworkPlayerManager -> PlayerControl`
6. `Shared/DJRNetLib/Packet/*`

这个顺序最容易看清“输入怎么进去，状态怎么回来，对象怎么同步”。

## 13. 结论

当前项目在架构上已经具备了一个多人在线动作游戏原型的核心骨架：

- 有统一启动入口
- 有客户端和服务端分工
- 有共享协议
- 有服务端权威实体
- 有客户端还原链
- 有基础 UI 和玩法对象

同时它也保留了原型项目常见的特点：

- 单例较多
- 资源路径硬编码
- DTO 与业务状态耦合
- 客户端网络层仍直接暴露协议包

但整体方向是清晰的，尤其服务端已经开始从“直接耦合”向“接口装配 + 命令处理 + 快照同步”演进。
